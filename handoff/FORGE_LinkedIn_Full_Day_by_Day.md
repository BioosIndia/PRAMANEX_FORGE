## Day 01 — Before the build: start with the document problem

**Purpose:** Problem framing

### Copy-ready draft

Before writing FORGE, I started with a documentation question: how can a reviewer trace a CMC statement back to the exact source that supports it?

CMC work brings together product information, batch records, analytical results, methods and many revisions. A polished draft is useful only when the evidence, missing information and unresolved discrepancies remain visible.

I chose a bounded portfolio exercise around that problem. FORGE would help organize source-backed facts and draft candidates while keeping a qualified CMC, RA or QA professional responsible for the decision.

This series shares the build and its working evidence. It is independent portfolio work, not employment, client delivery or commercial submission experience.

## Day 04 — Original evidence before a generated summary

**Purpose:** Source intake

### Copy-ready draft

A source-backed fact begins with the original record.

FORGE retains source identity, version, original bytes and a hash before accepting extracted candidates. The workflow can return to the record behind a value instead of treating a copied table or generated paragraph as the source of truth.

Permission, file type, parsing limits and revision checks belong at intake. When extraction is unsupported, the result should be an evidence request or HOLD—not a confident reconstruction of missing content.

The repository includes public official-document fixtures and separately labelled synthetic product records. Public guidance is not company product data, and a synthetic source is not a commercial batch record.

That distinction is central to how I present this portfolio work.

## Day 05 — Numbers and units need their context

**Purpose:** Analytical documentation

### Copy-ready draft

A number without its unit, batch and method context can be misleading.

FORGE keeps candidate values tied to source spans and revisions. Its parsing checks retain original numeric wording and reject unsupported precision or malformed table structures rather than quietly repairing scientific data.

In the synthetic work sample, assay is a percentage attached to an explicit batch record. It is not automatically converted into a conclusion about product quality.

This project helped me connect analytical skills with documentation discipline: preserve the reported value, make ambiguity visible and ask for the missing evidence before drafting a conclusion.

The tests show defined fixture behavior. They do not establish the accuracy of every real laboratory record or qualification for commercial CMC use.

## Day 08 — Authoring and checking are different jobs

**Purpose:** Technical QC / HITL

### Copy-ready draft

A draft should not approve itself.

FORGE separates source-linked draft candidates, deterministic technical QC and named human review. A model-generated statement remains a candidate even when it is grammatically clear.

The reviewer needs the current source revision, unresolved gaps and the relevant scientific context. An administrator account is not a substitute for qualified review authority.

The system can organize checks and record an exact-revision decision. It cannot supply the professional judgement that makes a commercial CMC conclusion acceptable.

This separation is part of the current engineering workflow and is tested with synthetic cases. It is not a claim of GxP validation or a certified electronic-signature system.

## Day 09 — Review only the version you actually checked

**Purpose:** Revision control

### Copy-ready draft

An approval belongs to a specific version of the evidence and output.

FORGE preserves revision-bound decisions. A changed source or affected dependency makes the relevant downstream work stale and requires fresh review; historical snapshots remain reconstructable.

The control matters when a document is updated after drafting, when a reviewer is working from an older screen or when two people attempt a change at the same time.

The safe response is to preserve the old decision as history and reject an unsupported current action—not silently move approval onto new content.

This is a bounded technical control demonstrated by the repository tests. Organizational review procedures, identity governance and qualified use still need their own evidence.

## Day 13 — Provider downtime should not erase the work

**Purpose:** Failure recovery

### Copy-ready draft

When an AI provider is unavailable, the application still needs a truthful state.

FORGE preserves bounded runtime tasks, leases, attempt limits and failure traces. A provider failure does not become a completed scientific draft. Stale work cannot overwrite a newer revision, and repeated requests must not create duplicate controlled effects.

Deterministic evidence work and human review remain distinct from optional model execution. Missing credentials or unsupported responses stay visible instead of generating fake success.

The current tests exercise defined local and synthetic failure conditions. Unattended scheduling, sustained provider behavior and production incident recovery are separate acceptance work.

A useful CMC assistant needs a clear stop condition as well as a successful path.

## Day 14 — Controlled branches preserve the original decision

**Purpose:** Lifecycle / change

### Copy-ready draft

Changes should be reviewable without rewriting the original approved record.

FORGE’s controlled branches keep an unchanged base and a separate proposal. A changed base, source or policy blocks a stale review or merge. Current reviewer authority is rechecked when a change is committed.

A proposal approval does not become scientific approval or regulatory release. The merged result is new candidate work that must pass the applicable review boundary.

This is useful documentation thinking: preserve what was known, record what is proposed and make the effect of a change inspectable.

The implementation and synthetic tests are available in the source package. They do not replace an organization’s change-control SOPs.

## Day 19 — Manual → assisted → controlled

**Purpose:** Professional value

### Copy-ready draft

I see FORGE as digital support for a professional workflow.

Manually, a CMC professional opens records, finds facts, compares sources, identifies missing evidence and prepares content. Assisted work can surface candidate facts, organize discrepancies and prepare a structured draft.

Controlled work adds the important boundaries: source links stay attached, missing evidence remains visible, changed revisions trigger fresh review and a human retains authority.

I have not claimed that FORGE replaces CMC or RA professionals, or that it saves a measured percentage of their time. Those outcomes need a comparable baseline and a supervised professional pilot.

The present proof is the connected workflow and the evidence a reviewer can inspect.
